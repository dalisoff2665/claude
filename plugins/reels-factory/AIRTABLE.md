# Airtable: что добавить, чтобы конвейер замкнулся

База `appspFv4OyALMTk8K`. Всё ниже — на существующих таблицах, новых не нужно.

## 1. Дедупликация — формула, которая уже работает

Проверено на живой базе: возвращает очередь неиспользованных референсов,
среди них ролики с 4.1 млн и 2.4 млн просмотров.

```
AND(
  {SCORE} >= 8,
  {decision} = 'ACCEPT',
  COUNTA({CONTENT PLAN}) = 0,
  DATETIME_DIFF(TODAY(), {Дата}, 'days') < 120
)
```

sort: `SCORE` desc, `videoPlayCount` desc · maxRecords: 3

**Вся механика «уже брал / не брал» — это третья строка.** Когда WF-2 создаёт запись
в CONTENT PLAN, он ставит link на запись в «Конкуренты - Анализ». Этот референс
больше не всплывёт никогда, а `сколько Использовали` в «Список Конкурентов»
начнёт считать.

Сейчас связь не ставится ни одним воркфлоу — поэтому база копится, а руки не доходят.

## 2. Фильтр выброса для ночного скрейпа

Не «свежие», а «доказавшие формат»: ролик, набравший вдвое больше медианы
своего аккаунта.

Поле в «Список Конкурентов», тип rollup по связи «Конкуренты - Анализ»:

```
Имя:      Медиана просмотров
Rollup:   videoPlayCount
Функция:  MEDIAN(values)
```

Фильтр в WF-1 после скрейпа:

```
{videoPlayCount} > {Медиана просмотров (from Список Конкурентов)} * 2
```

Без этого фильтра база снова забьётся шумом за месяц.

## 3. Статусная машина в CONTENT PLAN

Поле `СТАТУС СОЗДАНИЕ` — добавить опции, если их нет:

| Статус | Кто ставит | Что дальше |
|---|---|---|
| `Сценарий готов` | WF-2 | ждёт A-roll или отправки аватару |
| `Отдать аватару` | ты или расписание | WF-3, ветка HeyGen |
| `В монтаже` | WF-3 | идёт рендер |
| `На апрув` | WF-3 | ждёт твою кнопку |
| `Правка` | кнопка «Переделать» | WF-3 с этапа EDL |
| `Отклонено` | кнопка «Искать ещё» | WF-2 берёт следующий референс |
| `В очереди` | кнопка «Одобрить» | публикация в ближайший слот |
| `Опубликовано` | WF-4 | конец |

Поля под новые форматы головы (добавить в CONTENT PLAN):

| Поле | Тип | Значения |
|---|---|---|
| `Формат головы` | singleSelect | Сплит · Сплит наоборот · Вырезанный · Прыжок · Кружок |
| `Доля демо` | number | 15–85, по умолчанию 62 |
| `Пресет монтажа` | singleSelect | slides · yapping · split · scene |
| `Темп речи` | singleSelect | 1 · 1.1 · 1.2 |

Эти четыре поля — весь вход монтажёра. n8n читает их и кладёт в бриф
для обёртки Claude Code.

## 4. Три кнопки апрува

Кнопки уже есть в таблице (`Approve`, `опубликовать`). Нужны три разных вебхука:

```
Одобрить     → https://n8n…/webhook/reel-approve?rec={record-id}
Переделать   → https://n8n…/webhook/reel-redo?rec={record-id}
Искать ещё   → https://n8n…/webhook/reel-next?rec={record-id}
```

Вебхуки n8n принимают только `rec`. Не передавай в URL ничего, кроме id записи:
всё, что в адресе, оседает в логах и в истории браузера.

Страница `clony.agent-cleaner.com/approve?rec=…` уже существует — три кнопки
добавляются туда, на бэкенде они дёргают эти вебхуки.

## 5. Что вычистить перед запуском

В «Конкуренты - Анализ» накопились записи со `SCORE 9` и `decision: ACCEPT`,
не связанные ни с одной записью CONTENT PLAN, и часть из них датирована 2023 годом.

Перед первым запуском WF-2 прогони один раз:

```
AND(
  COUNTA({CONTENT PLAN}) = 0,
  DATETIME_DIFF(TODAY(), {Дата}, 'days') > 180
)
```

и проставь этим записям `decision = SKIP`. Иначе конвейер начнёт делать ролики
про инструменты трёхлетней давности.
