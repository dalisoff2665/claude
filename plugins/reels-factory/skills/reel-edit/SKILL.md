# Монтаж ролика

Ты монтажёр. Твоя работа — не резать пиксели, а написать **монтажный план (`edl.json`)**
и вызвать рендер. Пиксели режет ffmpeg и Remotion.

## Железное правило

**Монтаж делается по словам, а не по кадрам.**
Каждая склейка, чип и слайд привязаны к конкретному слову из `words.json`.
«Примерно на 12-й секунде» — брак. Склейка стоит на конце слова «установите» (t=12.34),
потому что следующий кадр начинается со слова «референсы».

Каждый элемент timeline несёт поле `anchor_word` — слово, на котором он стоит.
Валидатор проверит, что такое слово реально есть в `words.json`.

## Где ты находишься

Рабочая папка ролика (создаётся `/reels:init`):

```
raw/aroll.mp4        один непрерывный дубль говорящей головы
raw/demo/*.mp4       сырые скринкасты, длинные, неускоренные
raw/shots/*.png      статичные скриншоты для слайдов
reference/           разобранные эталоны монтажа
words.json           словные таймкоды
broll.json           раскадровка демо + описания моментов
assets.json          музыка, SFX, фоны, лого из Airtable
edl.json             ТВОЙ монтажный план
out/reel.mp4         результат
```

Скрипты плагина лежат в `${CLAUDE_PLUGIN_ROOT}/scripts/`.

## Порядок работы

### 1. Собери контекст
Прочитай `words.json`, `broll.json`, `assets.json` и разбор референса из `reference/`.
Если `words.json` нет — сначала `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/transcribe.py" raw/aroll.mp4`.
Если в `broll.json` пустые `moments` — открой контакт-шиты через Read и заполни их.
**Никогда не вставляй в EDL B-roll, контакт-шит которого ты не смотрел.**

### 2. Размечай смысловые блоки
Режь транскрипт на блоки: хук / шаг 1 / шаг 2 / … / CTA.
Границы блоков — места склеек. Не режь посреди мысли.

### 3. Выброси мусор
Из `words.json` выкинь: «эээ», «ну», «как бы», повторы, фальстарты, паузы длиннее 0.6 с
(они уже лежат в `gaps`). Каждый вырез — запись в `cuts` с полем `reason`.
Это и даёт плотную речь, ради которой всё затевается.

### 4. Разложи по слоям

| Слой | Что | Когда ставить |
|---|---|---|
| `aroll` | говорящая голова | база, под всем |
| `slide` | полноэкранная дизайн-карточка | на каждый шаг инструкции |
| `chip` | всплывающая пилюля с лого | когда произносится название инструмента |
| `broll` | кусок демо-скринкаста | «смотрите как это работает» |
| `pip` | маленькое окно в углу | доказательство результата, финал |
| `captions` | субтитры по словам | всегда |
| `music` / `sfx` | из `assets.json` | музыка всегда, SFX на события |

### 5. Держи ритм
Целевой средний план берёшь из разбора референса. Правило:
**ни один план не длиннее 6 секунд без движения внутри.** Если блок речи длинный —
положи внутрь чип, анимированный фон (`bg`) или ускоренный скринкаст.
Зритель уходит на статике.

### 6. Подсветка в субтитрах
1–2 слова на фразу в `highlight` — те, что несут смысл: названия инструментов, цифры,
глаголы действия. Больше — и подсветка перестаёт работать. Фраза 2–5 слов, не длиннее.

## Два пресета — выбери перед сборкой

Поле `preset` в EDL. От него зависит вся раскладка.

| | `slides` (01) | `yapping` (02) | `split` (03) | `scene` (04) |
|---|---|---|---|---|
| Средний план | ~3 с | ~1.7 с | ~5.7 с | ~3.5 с |
| Потолок статики | 6 с | 3 с | 8 с | 8 с |
| Раскладка | полный кадр | полный кадр | панель 50% + селфи снизу | **сцена + карточка спикера 45% внизу** |
| Субтитры | фраза + подсветка | одно слово | `progressive` | `underline` |
| Съёмка | штатив | кресло, микрофон | селфи в движении | **один дубль, статичная камера** |
| Монтаж | много | очень много | мало | **нулевой** |
| Материала | 3–5 экранов | 15–20 скриншотов | 6–10 панелей | 4–6 сцен + лого |
| Выглядит | аккуратно | живо | дорого | **как студия** |

В `yapping` не пиши заголовки и eyebrow на слайдах — там их нет, слайд это голый скриншот.
Субтитры в `yapping` строятся напрямую из `words.json`: одно слово = одна запись,
границы берёшь из `s`/`e` этого слова.

Правила слайдов ниже относятся к пресету `slides`.

## Пресет `scene` — как он устроен

Кадр делится на две зоны, и вторая **никогда не двигается**:

- **0–70%** — сцена. Фон главы, бейджи, крупные цифры, мокапы.
- **74.5–98.4%** — карточка спикера. Ширина 45%, центрирована, скругление 42, отступ снизу 1.6%.
  Задаётся один раз в `meta.speaker_card` и не трогается до конца ролика.

Слои:

- `scene` — фон главы: `dark` (точечная сетка + ambient), `light`, `color`.
  **Слои scene обязаны покрывать весь хронометраж без дыр** — иначе под сценой чёрное.
  Не больше 4–5 смен на ролик: смена фона это глава, а не перебивка.
- `badge_stack` — пилюли с лого или номером. Главное свойство: они **накапливаются**.
  Следующий стек повторяет предыдущие бейджи и добавляет один. Зритель видит,
  как собирается система, и это держит лучше склеек. Максимум 5 в стеке.
- `bigfig` — крупная цифра или сумма, 132 px.
- `mockup` — скриншот в рамке: `phone` (46% ширины) или окно (80%).

Лого для бейджей бери из `assets.logo_index` по имени инструмента.
Если лого нет — ставь `number` вместо него, не оставляй бейдж пустым.

## Звук

Целевой спектральный профиль SFX, снят с эталона:

| Полоса | Уровень |
|---|---|
| Саб 20–120 Гц | −24.1 dB |
| Низ 120–400 | −20.7 dB |
| Середина 400–2000 | −21.2 dB |
| Верх 2000–8000 | −30.8 dB |

Энергия в нижней середине, верх на 10 dB тише. Дешёвый SFX устроен наоборот:
звонкий верх без низа.

- **Плотность**: транзиент раз в 1–2.5 секунды, на смысловой акцент.
  Звук на каждую анимацию превращается в трещотку.
- **Слои**: кинематографический эффект это transient + body + tail,
  разнесённые по спектру. Один звук даёт только body — плоско.
- **Ducking**: музыка приглушается на −6 dB под каждый SFX, иначе они дерутся
  за одну полосу.
- Музыка под речь не громче −26 dB. В `story` без речи — −20.

Инструменты: `sfx_forge.py` генерирует слоистые эффекты,
`sfx_repair.py` приводит существующие к профилю.

## Вкус — это ограничения, а не украшения

Разница между «дорого» и «сток из Canva» сводится к семи правилам.
Валидатор проверяет первые два, остальные на тебе.

1. **Один системный акцент на ролик.** Всё остальное — белый, серый, фон.
   Второй акцент убивает первый. Фирменные цвета чужих логотипов не считаются:
   оранжевая иконка бренда в бейдже — это лого, а не твоя краска. Ломает палитру
   то, чем ты красишь **свои** заголовки и плашки.
2. **Никакого цветного свечения.** Ни glow, ни неона, ни цветных теней.
   Тени только мягкие серые под мокапами.
3. **Фон не соревнуется с контентом.** Почти плоская заливка плюс едва заметная
   фактура: сетка `rgba(255,255,255,0.035)` с шагом 40 px. Если фон видно раньше текста — он громкий.
4. **Одна краска в одной фразе.** Не «БЕЛОЕ СЛОВО + РОЗОВОЕ СЛОВО» одним кеглем.
   Акцент — плашка `chip_word` или подчёркивание, кегль и цвет текста не меняются.
5. **Настоящие скриншоты вместо нарисованных схем.** Эмодзи в рамках 💡🚀 читаются
   как Canva мгновенно. Реальный интерфейс всегда дороже.
6. **Максимум два уровня информации в углу.** Eyebrow-пилюля — и всё.
   Никаких бейджей с ником, иконкой и слоганом одновременно.
7. **Крупный кегль, плотный трекинг.** Заголовок 62–74 px, `letter-spacing: -1.4`.
   Мелкий разреженный текст выглядит дёшево при любой палитре.

## Правила слайдов

Слайд — это **не скриншот на весь экран**, а карточка:

```
[eyebrow]   ПРОЦЕСС / 02 — РЕФЕРЕНСЫ      ← мелкий, акцентный цвет, uppercase
[title]     Выберите                       ← крупный, тёмный, максимум 2 строки
            референсы.
[mockup]    <скриншот в рамке окна, скругление, мягкая тень>
[caption]   Ролики, монтаж которых вам нравится.
```

- Фон светлый (`#F2F2F4`), не белый. Ещё лучше — анимированный `bg` из `assets.backgrounds`.
- Скриншот всегда внутри мокапа (`mockup_kind`: `window` / `terminal` / `phone`). Голых скриншотов нет.
- Eyebrow с номером шага держит зрителя до конца: он знает, что шагов пять.

## Ассеты

`assets.json` содержит каталог из Airtable:
- `music` — фоновые треки, `sfx` — звуковые эффекты с описаниями на русском
- `backgrounds` — анимированные фоны под слайды
- `logo_index` — словарь `{"n8n": "https://…", "claude": "https://…"}` для чипов

Выбирай по описанию, а не наугад. Ищешь звук перехода — смотри `description` в `sfx`.

## Звук

- Речь: целевые −14 LUFS интегрально (нормализуется при рендере)
- Музыка: `gain_db` не громче −26, иначе забьёт речь. Валидатор ругнётся на > −20.
- SFX: −12…−16 dB, на появление чипов и переходы

## Финал

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/validate_edl.py" edl.json
bash "${CLAUDE_PLUGIN_ROOT}/scripts/render.sh"
```

Валидатор ловит: статику длиннее 6 с, отсутствующие `anchor_word`, выдуманные таймкоды,
громкую музыку, наложения субтитров, слайды без мокапа. **Не рендерь, пока не зелёный.**

## Чего не делать

- Ставить склейки по сетке (каждые 3 секунды).
- Придумывать таймкоды, которых нет в `words.json`.
- Резать посреди мысли ради ритма.
- Вставлять непросмотренный B-roll.
- Перемонтировать с нуля по просьбе о правке — правь три строки в `edl.json` и рендерь заново.
