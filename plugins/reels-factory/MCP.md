# MCP под видео: что ставить, а что не надо

## Главное решение

**Видео через MCP не гоняется.** MCP — это JSON по HTTP. Файл на 200 МБ туда не влезает,
а если влезет — ты заплатишь токенами за base64 и получишь таймаут. Поэтому:

- **Монтаж — локально.** ffmpeg, Remotion, faster-whisper работают на твоём Mac,
  Claude Code запускает их Bash-ом. Никакого MCP в этом цикле.
- **MCP — только для метаданных и ассетов.** Airtable (что монтировать), Cloudinary
  (куда положить результат), генерация картинок/видео (вернёт URL, не файл).

Если кто-то предлагает «MCP для монтажа видео» — это обёртка над ffmpeg,
которая делает то же самое, но медленнее и с лишним слоем.

## У тебя уже есть — трогать не надо

| MCP | Роль в пайплайне |
|---|---|
| Airtable (свой + официальный) | музыка, SFX, фоны, лого, контент-план |
| Cloudinary | заливка готового, раздача ассетов |
| kie.ai (свой) | Seedance / Seedream / Veo когда нужен сгенерённый B-roll |
| Gemini-медиа (свой) | картинки для слайдов на кредитах Google |
| HeyGen + HyperFrames | аватар, если ролик без съёмки |
| Apify | скрейп рилсов конкурентов |
| Playwright | скриншоты интерфейсов для слайдов — прямо со страницы, без ручной съёмки |

Playwright у тебя уже поднят и он здесь недооценён: скриншоты для мокапов на слайдах
можно снимать автоматически в нужном разрешении, а не руками через Cmd+Shift+4.

## Чего не хватает — одно

**ElevenLabs MCP** (`elevenlabs/elevenlabs-mcp`, официальный). Три вещи, которых
больше нигде нет в одном месте:

- `text_to_sound_effects` — генерация SFX по описанию. У тебя в Airtable 15 звуков,
  и для шестнадцатого приходится искать по стокам. Здесь: «резкий цифровой сбой, 0.4 сек» → файл.
- `text_to_speech` — озвучка, когда снимать некогда.
- `isolate_audio` — вычистить речь из шумного дубля. На GH4 с комнатной реверберацией пригодится.

```bash
claude mcp add elevenlabs --scope user \
  -- uvx elevenlabs-mcp
```

Ключ — в переменной окружения `ELEVENLABS_API_KEY`, не в команде и не в конфиге в открытом виде.

## Модель угроз (по твоему правилу нулевого шага)

Ставим один MCP и трогаем одну существующую поверхность.

**ElevenLabs MCP:**
- Достучаться до endpoint может только процесс на твоём Mac — это stdio-MCP, локальный,
  сетевого листенера не открывает.
- Утечёт строка конфига → утечёт `ELEVENLABS_API_KEY`. Последствие: чужие генерации
  за твой счёт, доступ к твоим клонированным голосам. Твой голос в их библиотеке —
  это не «списали $20», это дипфейк с твоим тембром.
- Поэтому: **отдельный ключ только под этот MCP**, права на генерацию, не на управление
  аккаунтом. Ключ в `~/.config/…/.env` с `chmod 600`, вне git. Ротация раз в квартал.

**Cloudinary в `publish.py`:**
- `CLOUDINARY_URL` содержит API secret. Он даёт право удалить всю твою медиатеку —
  а там CLONY, кейсы, обложки, 898 лого.
- Скрипт читает его из окружения и никогда не логирует. Проверь, что `.env` в `.gitignore`
  до первого коммита, а не после.
- Лучше: под публикацию завести отдельный upload preset с ограничением на папку `REELS_READY`,
  а не использовать мастер-ключ.

**Airtable PAT:**
- Scope только `data.records:read` + `data.records:write`, и **только на базу
  `appspFv4OyALMTk8K`**. Не на аккаунт. В базе `CONFIG` лежат `IG_USER_TOKEN`
  и `IG_PAGE_TOKEN` — с PAT на весь аккаунт утечка одного ключа отдаёт твой Instagram.

Быстрый вариант: один PAT на всё, и погнали. Что откладываем: раздельные ключи
и upload preset. Риск: одна утечёнка `.env` = медиатека + Instagram-токены.
Полчаса работы, чтобы закрыть.

## Чего точно не надо

- **MCP-обёрток над ffmpeg** — медленнее прямого Bash.
- **Ещё одного скрейпер-MCP** — Apify и Playwright уже перекрывают.
- **Универсального `run_command` в повседневном коннекторе** — у тебя такой уже есть
  на CRM-серверах, и для монтажа он не нужен. Claude Code и так имеет Bash локально.
